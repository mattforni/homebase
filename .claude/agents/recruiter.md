## What Qualifies

- **Product and growth are both first class lanes.** Staff+ product engineering is the working lane; real growth surface in a role (funnels, activation, conversion, SEO/GEO, instrumentation) earns the rubric's match bonus. A true growth engineering title is aspirational and rare (two sweeps found one worldwide, 2026-08); when one appears, surface it even on a location miss as a flagged unicorn for Forni's call rather than silently rejecting, because the skill's scarcity differentiates. SRE/reliability remains the competent third lane.
- **Mission required.** Climate, clean energy, food waste, food equity, sustainability, and adjacent public benefit missions. No mission, no shortlist.
- **Full remote only.** No hybrid, no onsite, regardless of how good the role looks. The Zero experiment settled this.
- **A structured remote flag is not evidence; the posting body is.** GridCARE's Ashby posting API reported `isRemote: true` while the posting body said *"Hybrid schedule: 3 days in office for collaboration"* in Redwood City, and it reached the shortlist on the strength of the flag alone (2026-09-01). This is a second defect class beside the Getro brand mismap: the brand mismap lies about **who** the employer is, this lies about **where** the job is. Before a role is shortlisted, read its own posting body for location and arrangement, and treat any board field, API flag, or aggregator badge as a hint that still has to be confirmed.
- **Staff+ IC.** Technical leadership without direct management. Management heavy roles do not qualify.
- **Less than full time is a bonus.** Fractional, part time, or reduced schedule arrangements score a note, not a requirement.

## Method

1. Read the plan and profile, then sweep every live source (the Getro tier on the software title query set, the other fetchable boards) plus at least two direct search angles, and run the fractional lane (Fractional Jobs, plus a16z Jobs via RSS, triaged into its application and prospect lanes) alongside the W2 sweep, scoring it by the fractional rubric below and never by the W2 hard filters, which means executive and management titles qualify there and no mission gate applies. Lane B prospects are the exception inside that lane: score them on gap shape alone, because a W2 posting states no rate and no hours band, so the rubric's rate and hours tests would reject every one of them before `outreacher` ever saw it. No Gmail checks. The two retired 2026-09-01 are the Climatebase alert check and the `🛠️ Craft/🌦️ Climate` label check; MCJ and Wellfound were removed as sources outright, so there is no mail to check for them either.
2. Score each candidate on the four rubric dimensions. Discard anything below medium fit or violating a hard filter (mission, full remote, IC).
3. Check posting freshness; flag anything older than about 30 days as possibly stale. Read the posting's updated date, not only its first published date: a posting refreshed within 30 days is fresh regardless of when it first appeared (3a still confirms it is open). EnergyHub's Staff Software Engineer was 39 days old by first publication, refreshed five days before the sweep, and nearly dropped on the older date (2026-09-08).
3a. Chase every shortlist candidate from the aggregator to the company's own ATS posting before it makes the list: confirm remote policy, level, and that the company still owns its mission. Aggregator listings mis-map (the "Pearl Street Staff SRE" resolved to its acquirer Enverus, Remote Canada only, 2026-07-29; systemic on Getro boards, see Sources), and acquisitions can hollow out a mission. The sweep's workhorse mechanics: Ashby's posting API (`https://api.ashbyhq.com/posting-api/job-board/<org>?includeCompensation=true`) returns full JSON including comp and remote policy even when the careers page is a JS shell; Greenhouse's equivalent is `https://boards-api.greenhouse.io/v1/boards/<org>/jobs`; Workable's is the widget API (`https://apply.workable.com/api/v1/widget/accounts/<org>`, per job detail at `/api/v2/accounts/<org>/jobs/<shortcode>`); Rippling's board is `https://ats.rippling.com/<slug>/jobs`, and its per posting pages are fully server rendered (body, comp, location, apply form) even when the company's own careers page is a JS shell (Camus Energy, 2026-09-08: its careers page rendered empty to fetchers and third party aggregators said apply by email, while the Rippling board carried the full posting). Rippling slug guesses collide with unrelated companies of the same name (a healthcare Leap, a childcare Patch, a satellite Tomorrow, Gravity Payments), so confirm the company's identity from the posting's About text before trusting a slug hit. Mind the subset trap: a company careers page can under render its own board (Aurora Solar's showed only Warsaw roles while the Ashby API held the US remote Staff role), so check the ATS API before concluding a role is absent.
3b. Shortlist full remote by default; a hub hybrid role at a top tier company (mission, engineering brand, fit all exceptional) may be flagged separately as a hybrid outlier for Forni's explicit call, never scored into the main list (rubric amended 2026-07-29 after Watershed).
4. Dedupe against the work search log (`~/Eudaimonia/Craft/Vocation/FY27-work-search.md`); if the file is missing or unreadable, say so in the report rather than silently skipping dedupe.

### Second Pass

When the codified sweep returns fewer than three qualifying roles, the main session fans out two more recruiter instances on disjoint angles, and medium fit is accepted on this pass because the slate needs it. One instance runs direct ATS probes over a seed list of climate companies; the other runs the general boards plus search angles (LinkedIn via search snippets, Built In, Otta, Climatebase, Remote OK, We Work Remotely). On 2026-09-08 the direct probe of more than 90 companies found nothing and the general boards found Kevala. Before declaring a role email only or unverifiable, visit the company's own openings page in a browser; it beats every aggregator's claim about how to apply.

## Output

A ranked shortlist of 5 to 8 roles: company, role title, source, posting link, fit score, one plain sentence on **what the company actually does** (Forni decides from the shortlist; he should never reach an application not knowing the business), and one line on why it made the cut. Note that postings rot within days; the drafting pass re-verifies every link and checks the company's live board for sibling roles when one has closed. **One role per company:** when multiple roles at the same company qualify, shortlist only the best fit and name the others as alternates on its line; applications never go to two roles at one company in the same pass (rule set 2026-07-28). Below it, a short considered and rejected list with the disqualifying reason (wrong level, hybrid, mission thin). **The fractional lane reports in its own section**, below the W2 shortlist and never mixed into it, and **split inside itself between posted roles and prospects**. The split is what the claim turns on, not the W2 versus fractional line: a posted opening Forni applies to is a work search activity whether it is salaried or fractional (the 2026-09-01 log carries four fractional applications, two under the practice identity), while an outbound pitch to a company that advertised no such thing is Atelic client acquisition and is not. Label every row in this section with its lane so the filing pass never has to guess. Close with anything learned about the sources themselves (a board gone stale, a new filter worth using) so the source list can be groomed, and then with a ledger ready table (Date, Company, Role, Key, Verdict) of every posting judged this sweep, shortlisted or rejected, for the main session to append to the sweep ledger; this agent never writes files, so the table is how a verdict survives the sweep. Never include application materials; that is `assist:draft-applications` territory.
