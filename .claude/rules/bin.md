# bin/ Scripts and the Lint Gates

Loaded when a script, the git hooks, or the CI workflow is read.

## bin/ Script Conventions

New scripts live in a namespace folder named for their tool or domain, with verb noun filenames: `bin/vault/push-secrets`, `bin/vault/push-gws-secrets`. Because `~/bin` is a single symlink to the repo's `bin/`, nested folders deploy with no extra plumbing. Legacy flat scripts (`checkout-branch.sh`, `sync-marketplaces`) migrate into namespaces opportunistically when next touched.

**Flat files are shims; directories are namespaces.** A shim shadows a real binary of the same name on PATH (`bin/gws`, `bin/hs`, `bin/toggl`), so it has to be a flat executable sitting directly in `bin/` where PATH lookup finds it. Everything else goes in a namespace folder. The two collide the moment a tool needs both, and the shim wins the bare name: `bin/gws/push-secrets` moved to `bin/vault/push-gws-secrets` on 2026-08-07 to free `bin/gws` for the profile shim, which also consolidated the two secret pushers under one namespace. When adding a shim, check that `bin/<tool>` is not already a directory, and remember a directory is also `-x`, so any "find the real binary on PATH" loop needs a `! -d` guard or it will happily try to exec the folder.

**Shared logic lives in `bin/lib/`, sourced rather than duplicated.** `bin/lib/account-profile.sh` is the single implementation of `.account` marker parsing and profile resolution, sourced by `bin/gws`, `bin/hs`, `bin/toggl` and `.functions`. It exists because three copies drifted: a path traversal fix on 2026-08-07 had to be written three separate times and the third copy, in the since retired `bin/claude` wrapper, was missed twice before review caught it. Two rules when adding to `bin/lib/`:

**A shim routes identity and no longer gates writes.** `bin/gws` and `bin/hs` resolve identity. Until 2026-10-06 `bin/ynab` refused budget writes without `YNAB_APPLY=1` and `bin/hs` refused CRM writes without `HS_APPLY=1`. Both bumps came out that day on Forni's call: they stacked with the session's permission classifier, which read the flag itself as a bypass and blocked writes he had asked for. The gate on a write is the classifier plus his instruction in the session. `bin/ynab` is gone, so the real CLI runs from PATH.

- **A sourced library must never take the caller down.** `bin/gws` passes through untouched when the library is unreadable, since blocking the command it wraps would be worse than resolving the wrong profile. `.functions` leaves its resolver a no-op so the shell still starts. `setup.sh` is the deliberate exception and fails loudly, because it has nothing correct to do without its table. Guard every source with `[[ -r ... ]]` and define the degraded behavior explicitly.
- **Anything `.functions` sources must be zsh clean, not just bash clean.** Shims run under bash where `path` is an ordinary variable; `.functions` is read by zsh, where **`path` is special and tied to `$PATH` as an array**. A `local path=...` there silently clobbers command lookup for the rest of the function, so `tr` stops resolving and every marker reads as empty with the error swallowed by `2>/dev/null`. Avoid the zsh special names entirely: `path`, `status`, `prompt`, `cdpath`, `manpath`, `dirstack`, `argv`. Run `zsh -n` and an actual zsh resolution test, since `bash -n` cannot see this class of bug.

## Custom Git Branch Checkout

The `git cob` alias uses `bin/checkout-branch.sh` to checkout branches by their numerical position from `git branch` output. Usage: `git cob <number>`

### Linting

The gates below each run the same script locally and in CI: markdown, shell and the reconciler are the three the root `CLAUDE.md` names, and the rest are table tests on one script or hook each.

- **Markdown** — `npx markdownlint-cli2`. Globs live in both `.markdownlint-cli2.jsonc` and the workflow's `globs:` input, kept in sync. **Do not remove the workflow's `globs:` input.** The action's default is a single-asterisk `*.{md,markdown}` that matches only the repo root; without an explicit glob this job linted exactly two files from the day it shipped until 2026-08-11, while 94 findings accumulated behind it.
- **Shell** — `bin/lint/shell` runs shellcheck plus `bash -n` plus `zsh -n`, gated at warning severity so style noise does not train you into `--no-verify`. The `zsh -n` pass is the point: `.functions` must be zsh clean, and `bash -n` cannot see that class of bug. **A brand new script is invisible to it until staged**, because it discovers files through `git ls-files`. Running the linter after writing `bin/hs` reported clean over the same file count as before; `git add` first, then lint, or trust the pre-commit hook to catch it at the gate.
- **Reconciler** — `bin/lint/reconcile-test` clones to a scratch path and exercises `reconcile_home` against a throwaway `$HOME`, asserting migration, refusal, pruning, merge behaviour and idempotence.
- **Review normaliser** — `bin/lint/review-normalise-test` drives the normaliser in `bin/review/lib.sh` with canned reviewer output: the findings array in every accepted shape, prose and bracket fragments that must come out `ran: false`, the blocking and unrated counts, and the scorecard header. It exists because a shape that normalised to "zero findings" when nothing was reviewed would be a merge gate that fails open; add a row for every new shape a reviewer emits.
- **Runner email renderer** — `npm ci`, `npm run typecheck` and `npm test` in `runners/email`, on node 24 because that is what the runner images ship (`node:24-slim`). A bundle carries one runner's page, so there is no single build step: the test builds each runner's bundle through `build.mjs`, the way that runner's image does, renders four invented fixtures through the built files, and holds each against a frozen golden, html and text alike. It also holds that a bundle asked for another runner's page fails like an unknown name and that every bundle carries the failure page. `npm ci` installs exactly what `runners/email/package-lock.json` pins, so a bump to the `@atelic-action/ui` pin lands with its lockfile or the job fails. `bin/lint/runners` also stages every runner's build context and refuses a directory under `runners/lib`, which is copied flat into every image (a `tst/` there broke staging for every runner on 2026-10-07). The funnel rules a runner reads live in the Atelic repo at `plugins/atelic/scripts/lib/` and are tested by its CI, never here, and so is the runner that lives there with its page.
- **Promote path rules**: `bin/lint/runner-changed-test` drives `bin/runner/changed`, which decides which runner images a merge to main promotes (`.github/workflows/promote.yml`). It builds a throwaway repository with an invented `runners/` tree, commits one change at a time, and holds the printed list against the rule: the shared library, the renderer and the two scripts that decide what ships reach every runner; a runner's own files reach only it; a runner's page (`runners/email/<name>.tsx`) reaches only it, while every other file of the renderer reaches them all; a README, `mounts`, `out/`, `.build/`, `.env.local`, the renderer's tests, fixtures and goldens, and the `email/tst/` of a runner that keeps its own page reach nothing; a runner that leaves, with its page, its fixtures and the agent only it named, promotes nothing and is never printed itself; an agent reaches the runners whose `agents` manifest names it; a path a `context` manifest names as a source, or an `agents` line brings an agent from, reaches the runner that named it; an all zero, empty or missing base means every runner. A missed path fails silently, as a scheduled job on an old image beside a green run, so add a row whenever a new kind of file starts or stops reaching an image. It runs in the Shell job and in the pre-commit hook when the script, `bin/runner/lib.sh` or the test is staged.
- **A runner outside this repository**: `bin/lint/runner-outside-test` drives `runner_dir`, `runner_build_context` and `runner_email_bundle` in `bin/runner/lib.sh` against a throwaway repository holding an invented runner, since a runner may live in another repository whose workflow checks this one out for its tooling, and nothing here ever stages one for real. Each row holds one rule: a path resolves to the real directory and its name while a bare name still means `runners/<name>`; the shared library and the renderer come from here and the rest from the runner; the manifests never ship; an agent comes by name or by path; a `context` line lands at its dest and is refused when its source leaves the runner's repository (by `..`, an absolute path, or a symlink), when its dest leaves the context or is taken, or when it is not `source:dest`; a single file git ignores is refused as a `context` source and as an agent by path, since the dirty gate cannot see it; the runner's own `email/` lands beside the renderer and a clash of names is refused. Where `runners/email/node_modules` exists it also builds the invented page into a bundle and holds that a second directory of the same name never gets the first one's. Add a row for every new thing a manifest can ask for, since a refusal that stops holding puts a file from outside a repository into an image. It runs in the Shell job (no packages, so no bundle rows), again in the renderer job (with them), and in the pre-commit hook when `bin/runner/lib.sh`, `runners/email/build.mjs`, `runners/email/render.tsx` or the test is staged.
- **File landing and line reader**: `bin/lint/runner-land-test` drives `runner_land_file` and `runner_each_line` in `runners/lib/runner.sh`. It builds a throwaway bare repository, a one commit deep clone of it, and a second clone that pushes between the first one's clone and its push, then holds that the one file lands on the new tip with nothing else touched and the run's own checkout never moved, that a push which loses a race is retried and a push refused for any other reason is not, that a file somebody changed on main during the run is never pushed over, and that every way of not landing ends in a non zero return so the caller falls back. It runs with no global or system git config, so a machine that signs commits or sets hooks reads the same result. The line reader is held against lines with apostrophes and quotes and a line past 255 bytes. Add a row for every new way a landing can end. It runs in the Shell job and in the pre-commit hook when `runners/lib/runner.sh` or the test is staged.
- **Build wait**: `bin/lint/runner-build-test` drives `runner_build_wait` in `bin/runner/lib.sh`, where a promote's verdict comes from, against a fake `gcloud` on PATH that replays a scripted run of build statuses and records every call. Each row holds the exit code and whether a cancel was sent: only `SUCCESS` returns zero; a build that ended any other way returns one and sends no cancel; the deadline and a run of unreadable statuses past the limit each cancel the build exactly once. Add a row for every new way a wait can end. It runs in the Shell job and in the pre-commit hook when `bin/runner/lib.sh` or the test is staged, and takes about fifteen seconds because some rows have to let a real second pass.
- **Secrets gate** — `bin/lint/secrets-gate-test` drives `.claude/hooks/secrets-gate.sh` with a table of commands that must deny (anything that prints a `.env.local`, a gws credential file, or a vault export: `cat`, `head`, `cut`, `sed`, `awk`, `grep` without `-c`, `-l` or `-q`, a `$(cat ...)`) and must pass (`grep -c`, `wc`, `stat`, `ls`, `source`, a `gcloud ... | python3` move that never echoes). The hook exists because on 2026-09-21 a `cut -d= -f1` meant to list variable names printed two deploy keys and a mailbox token whole: multi line values have no `=` on their continuation lines. Add a row for every new way a secret nearly prints. `SECRETS_GATE_BYPASS=1` is the deliberate override.
- **Voice gate** — `bin/lint/voice-gate-test` drives `.claude/hooks/voice-gate.sh` with a table of `gws gmail` commands that must deny (`+send`, `+reply`, `+reply-all`, `+forward`, `drafts create`, `messages send`, while the session transcript shows no Read of `VOICE.md` and `Admin/Tools/email.md`) and must pass (the same commands once both are read, in the session or a subagent beside it; every read; `drafts send` of an existing draft). The hook exists because on 2026-10-05 an email drafted mid task went through four drafts with the voice canon unread, though GC already asked for it. `VOICE_GATE_BYPASS=1` is the deliberate override.

A tracked `.githooks/pre-commit` runs markdown and shell on staged files, and each runner test when the script it holds is staged. Activate it
once per clone:

```bash
git config core.hooksPath .githooks
```

**A comment whose first word is the analyzer's own name is parsed as a
directive**, whitespace-insensitively, and errors as SC1072 or SC1124. Lead
explanatory prose with something else. This bit three separate files while the
gate was being written, including the linter itself.
